# 四页底栏取代单页长滚动

移动端实测发现：单页首页在 Pixel 7 视口下约 5181 px（约 5.7 屏），每天必做的睡眠日记被压在说明、偏好、安全筛查与六周训练之后；底部没有固定入口，离开与返回都只能长距离滚动。因此把应用拆成今日、日记、训练、设置四个顶层页面，用固定在底部的底栏切换；设置内部再以列表 + 子页组织。地址采用 hash 路由（`#/today`、`#/diary`、`#/training`、`#/settings`），因为站点托管在 GitHub Pages 的静态子路径下，hash 不需要 404 回退，也不改变 Service Worker 的导航回退策略。

页面切换采用保活而不是卸载：日记表单是每天要填的，切到训练页看一眼睡眠窗口再回来，不能丢掉已经输入的内容；同时只有当前页面可交互、可聚焦。桌面宽度下沿用同一条底栏并限宽居中，不做第二套顶部导航——产品规格本就不承诺桌面布局，一套导航只维护一份焦点顺序与一套测试。

**Considered Options:** 保留单页、只加目录跳转（长页依旧，返回成本高）；history 路由 + 404 回退（地址更干净，但 Pages 与离线回退要多维护一份）；桌面独立顶部导航（两套导航、两套焦点顺序、两套测试）。

**Consequences:** 所有依赖「同屏可见多个面板」的既有端到端测试都要先导航再断言；Tab 顺序与触控目标检查要按页面分别执行。安全筛查从首页面板改为设置子页，因此「开始六周训练」以完成安全筛查为前提，但日记、导出与教育内容不设门槛，已有课程进度的用户不被回溯拦截。

**状态：** accepted
