# 睡眠行为训练器：产品与技术规格

**状态：** 已确认设计，待分票实现  
**目标：** 开源、中文首发、移动端优先的睡眠行为训练 PWA。  
**产品定位：** 帮助用户改善睡眠习惯的行为训练器；不是睡眠监测、诊断或治疗服务。

## Problem Statement

有睡眠困扰的人常能找到睡眠卫生知识、白噪音和可穿戴设备评分，却缺少一个轻量、私密、以行为练习而非被动监测为核心的中文工具。慢性失眠的有效干预需要结构化 CBT-I 行为成分；单独提供睡眠卫生知识不足以替代 CBT-I。现有设备睡眠分期也不适合直接作为睡眠限制的计算依据。

## Solution

提供一个本地优先、无账号、无遥测的移动端 PWA。应用以用户晨间填写的主观睡眠日记为数据源，通过六周结构化流程帮助用户建立固定起床时间、练习刺激控制，并在安全筛查通过后使用保守、规则化的睡眠窗口滴定。所有核心流程离线可用；完整备份通过用户主动保存的 ZIP 文件完成。

本应用不宣称诊断或治疗失眠，不读取穿戴设备或手机的被动睡眠数据，不用深睡评分驱动建议。量表 ISI 在复用许可和适用的中文版本均确认之前，不复制或纳入首版；首版使用自有非诊断性问卷。

## User Stories

1. 作为首次使用者，我想了解应用是行为训练而非睡眠监测或医疗诊断工具，以便理解其适用范围。
2. 作为用户，我想用中文完成入门流程，以便不依赖英文材料。
3. 作为用户，我想选择期望长期保持的固定起床时间，并看到基于近期实际起床时间中位数的预填建议，以便设定可执行的时间锚点。
4. 作为用户，我想回答自有的非诊断性睡眠困扰问卷，以便明确自己的改善目标，而不被赋予未经验证的临床等级。
5. 作为用户，我想完成安全筛查，以便在不适合自动睡眠限制时得到清晰的专业评估建议。
6. 作为未满 18 岁或有睡眠限制高风险情况的用户，我想仍能阅读教育内容、记录睡眠日记和导出数据，以便不被完全排除在工具之外。
7. 作为用户，我想记录关灯、SOL、最终醒来和起床时间，以便计算可用的睡眠指标。
8. 作为没有睡眠监测设备的用户，我想跳过难以回忆的夜醒次数或 WASO，以便仍能保存日记而不伪造精确数据。
9. 作为用户，我想把夜醒次数和 WASO 记为不知道、区间估计或精确估计，以便记录符合自己记忆精度的数据。
10. 作为用户，我想记录主观睡眠质量和咖啡因、酒精、午睡、运动等可选标签，以便回顾相关行为。
11. 作为用户，我想在一分钟左右完成晨间日记，且允许之后补充或修改，以便记录不会成为负担。
12. 作为用户，我想看到 TIB、TST、SE 等指标何时可计算、何时因数据不足不可计算，以便区分未知与零值。
13. 作为处于基线周的用户，我想先记录一周而不被要求立即改变行为，以便获得个人基准。
14. 作为用户，我想在第一周结束后预览候选睡眠窗口、在第二周建立固定起床与咖啡因习惯，并在第三周才启动睡眠限制，以便逐步进入训练。
15. 作为用户，我想在数据完整时看到规则化的每周窗口调整及其理由，以便理解建议来源。
16. 作为数据不足或生活事件发生的用户，我想保持现有窗口或推迟一次调整，以便不因缺失记录或短期变化被自动惩罚。
17. 作为用户，我想在睡前收到刺激控制规则的说明，但不被要求夜间打开手机或运行倒计时，以便手机不干扰床与睡眠的联结。
18. 作为出现强烈嗜睡、相关疾病史或其他红旗的用户，我想看到暂停睡眠限制的解释和建议就医信息，以便避免无监督的高风险干预。
19. 作为用户，我想只在自愿且支持的情况下启用系统通知，并在未授权时仍能使用全部核心功能，以便提醒权限不是使用前提。
20. 作为用户，我想离线填写日记、查看完整六周内容、查看安全说明并完成导入导出，以便网络中断不影响核心流程。
21. 作为本地优先用户，我想不创建账号、不上传健康数据且不被遥测追踪，以便睡眠数据留在设备上。
22. 作为用户，我想看到本地错误信息，并能自行决定是否将不含健康数据的错误诊断信息带到 GitHub issue，以便报告问题时不泄露睡眠记录。
23. 作为用户，我想导出包含日记、课程进度、设置和筛查状态的压缩 ZIP 备份，以便迁移到新设备。
24. 作为用户，我想导出易于查看的 CSV 睡眠日记，以便用表格软件分析；CSV 不承担完整恢复功能。
25. 作为用户，我想预览备份摘要并选择覆盖、新增或取消，以便明确控制导入对现有数据的影响。
26. 作为用户，我想在覆盖前再次确认，并在导入失败时保留原有数据，以便避免误删或损坏。
27. 作为用户，我想在积累三晚记录后收到备份提醒，并可在设置中关闭，之后最多每周收到一次，以便降低换机时丢失数据的可能。
28. 作为用户，我想知道 PWA 本地数据可能因清理浏览器数据、设备故障或换机而丢失，以便及时在设备之外保存备份。
29. 作为中文社区贡献者，我想翻译所有用户可见文案而无需修改代码逻辑，以便后续增加语言。
30. 作为低视力或使用辅助技术的用户，我想使用系统大字、对比度、VoiceOver 或 TalkBack 完成全部核心流程，以便不依赖颜色或精细触控。
31. 作为离线用户，我想在应用资源已缓存且后续版本更新失败时继续使用当前版本，以便更新问题不阻断日记与疗程。
32. 作为维护者，我想在稳定 HTTPS GitHub Pages origin 发布静态站点，以便首版不需要后端服务。

## Implementation Decisions

### 产品与疗程

- 平台：React + TypeScript + Vite 的移动端 PWA；首版不采用 React Native、Expo、Flutter、Ionic UI 或 Capacitor。未来若原生通知、文件或后台能力成为硬需求，可在现有 Web 应用上增加 Capacitor，保留领域规则和备份格式。
- 许可证：MIT。项目公开托管于 GitHub；首版部署目标为 GitHub Pages。GitHub Issues 承载 bug 与需求。
- 语言：中文首发；所有用户可见字符串、课程、安全提示、表单验证、错误、辅助标签和格式资源进入 i18n。首版资源随应用打包，不依赖在线翻译。
- 六周流程：W1 基线日记与自有非诊断问卷；W2 固定起床时间与睡前 8 小时咖啡因截止；W3 正式启动睡眠限制与刺激控制；W4–W5 每周滴定并穿插认知内容；W6 巩固与复发预防。第一周结束展示候选睡眠窗口，第二周后重新校准，第三周启用。放松练习作为后续内容，不作为单独治疗承诺。
- 固定起床时间：第一周由用户选择；近期实际起床时间中位数可作预填建议，用户确认后第二周执行。修改起床时间从下一周窗口周期生效，不即时重算当前窗口。轮班/倒班用户不进入自动睡眠限制流程。
- 用户可推迟每周滴定，不得自行编辑系统计算的睡眠窗口分钟数。

### 睡眠日记与计算

- 每条日记对应用户当地日期的一夜。记录关灯时间、SOL、最终醒来时间、起床时间；夜醒次数、WASO、睡眠质量（1–5）及咖啡因/酒精/午睡/运动标签可选。夜醒次数允许“不知道”、区间 `0 / 1–2 / 3–5 / 6+`；WASO 允许“不知道”、区间 `<15 / 15–30 / 30–60 / >60 分钟`、精确分钟或明确“整夜没有记得醒来”。不得把未知或区间伪装成精确分钟。
- 日记允许部分保存和之后补录。保存不依赖完整夜条件。缺失字段不等于 0。
- 只有全部必要字段完整、WASO 精确或明确零、时间顺序有效的记录才构成完整夜并参与 SE/窗口滴定；范围 WASO 和未知 WASO 可留在日记趋势中，但不用于精确 SE。夜醒次数不决定 SE 可计算性。
- `TIB = 起床时间 − 关灯时间`；`终末清醒 = 起床时间 − 最终醒来时间`；`TST = TIB − SOL − WASO − 终末清醒`；`SE = TST ÷ TIB × 100%`。跨午夜按日记所属本地日期解析；负时长、顺序矛盾、超出卧床时间的组成时长须要求用户修正，不能静默夹断为有效数据。
- 没有可计算指标时显示“数据不足/未知”，不得显示为 0。日记记录原始输入；派生指标按当前公式计算并可因公式版本升级而重建。

### 安全筛查与干预规则

- 首版不复制 ISI 完整题目，不显示 ISI 分数或临床严重度等级。只有在复用许可与适用的简体中文版本均确认后，才能通过另一个明确版本加入 ISI。自有问卷只询问睡眠困扰持续时间、最近一周受影响夜数、日间影响和用户目标；不计分、不诊断、不决定睡眠窗口。
- 安全筛查包括：年龄未满 18 岁；双相障碍/既往躁狂或轻躁狂；癫痫/惊厥；未经评估或未治疗的疑似 OSA（响亮鼾声、目击呼吸暂停、日间嗜睡、高血压等红旗）；危险性异态睡眠；妊娠；严重日间嗜睡、驾驶/高风险作业或急性不稳定状况。风险项表述为“需要专业评估/谨慎”，不宣称统一绝对禁忌。
- 高风险命中时暂停睡眠限制和自动滴定，仍允许记录日记、查看教育内容和导出；显示适合的专业评估提示。OSA 红旗、重度困扰自述等显示强就医建议，不阻止非限制性记录。筛查结果不能通过设置直接绕过；按产品规定重新筛查后才可恢复非限制性训练。不要提供诊断结论。
- 采用的产品窗口规则：首次候选窗口为最近 7 夜中完整夜 TST 的平均值 + 30 分钟，按最近 15 分钟舍入；不超过这些记录的平均 TIB，且不得低于 5 小时。5 小时是本项目保守产品下限，不称为统一临床标准。若完整夜少于 4 夜，继续基线/保持现有窗口并显示数据不足。
- W1 后只预览候选窗口，W2 收集固定起床行为后以最近 7 夜数据重算，W3 才正式启用。每周最多滴定一次，以最近 7 夜完整夜平均 SE 决策：`SE > 90%` 增加 15 分钟；`SE < 85%` 减少 15 分钟；`85% ≤ SE ≤ 90%` 保持。下限 5 小时。少于 4 个完整夜不变更窗口。允许用户推迟当周调整。
- 如果候选/新窗口超过 10 小时，暂停自动窗口并建议专业评估；任一计算窗口不得超过 12 小时。该 10/12 小时规则是产品边界，不宣称为临床指南阈值。
- 刺激控制文案：困倦后上床；若清醒且无法入睡/重新入睡，可在约 20 分钟这一近似时长后离床，困倦后返回；不要求夜间盯钟或操作手机。20 分钟不是硬性生理/指南阈值。
- 规则来源与限制见安全规则核查报告；这些规则为产品固定行为，不代表 AASM 对唯一算法的背书。

### 数据、导入导出与错误

- 不注册账号，不使用云同步、分析、广告或错误遥测 SDK；不上传日记、筛查、课程进度或本地错误。
- 用户数据保存在 IndexedDB；程序、课程、语言包和静态资源由 Service Worker/Cache Storage 管理。Cache 可重建，不能作为数据备份。用 `navigator.storage.persist()` 作尽力而为的请求，检查实际结果；配额和事务写入失败需本地提示，不能假报保存成功。
- 错误内容只在本地呈现，可供用户复制并自愿贴进 GitHub issue。诊断信息默认不含睡眠字段、筛查答案或健康数据；UI 提醒用户在公开 issue 前检查是否含个人信息。错误不自动发送。
- 完整迁移包为标准 ZIP 容器，内部 JSON/元数据，ZIP 条目使用 DEFLATE；不加密、不上传。JSON 包含 schema/app/规则/课程版本、导出时间、日记、疗程状态、设置和筛查结果，并含校验信息。扩展名采用 `.sleep-backup.zip`。
- 导出后通过浏览器下载/分享机制交给用户，并提示压缩不是加密；点击导出不等于外部备份已保存。CSV 仅导出日记，不用于完整恢复。
- 导入前读取 ZIP、校验条目/大小/schema/版本/校验和，生成备份摘要和与当前数据的对比；校验失败不触碰现有数据。未来未知版本拒绝导入并保留原数据。
- 导入三选一：覆盖（移除旧数据并完整恢复，二次确认）；新增（保留当前用户设置、疗程状态和安全筛查状态，只追加备份日记，按日记 ID 去重，ID 冲突以当前数据为准）；取消（无副作用）。
- 导入通过暂存/校验后再事务提交。失败回滚，不能留下半份迁移状态。
- 备份提醒默认开启：完成 3 晚后首次提示，此后每周最多一次；用户可在设置中关闭。提醒由用户再次进入应用时显示；不请求系统通知权限。系统通知只有在用户主动授权且能力支持时可作为可选增强，拒绝或不支持不影响核心流程。

### 离线、部署与界面质量

- 固定 GitHub Pages HTTPS origin。首次联网访问并确认资源缓存完成后才声明“可离线使用”；此前不保证首次离线打开。缓存应用壳、全套课程、翻译、安全文案和必要资源。离线核心功能包括日记、计算、疗程、筛查、ZIP/CSV 导入导出与设置。
- 新版资源准备完成后再切换；更新失败继续当前缓存版本。程序更新与 IndexedDB schema/内容版本迁移需兼容或可恢复，不通过清空数据来升级。
- PWA 安装不等于永久保存。清除浏览器/站点数据、设备重置/故障、隐私模式和换机未迁移可能丢失本地数据；界面提供清楚的备份说明。桌面布局不在首版承诺范围。
- 目标为 WCAG 2.2 AA；首发支持当前及前一主要版本的 iOS Safari 和 Android Chrome（按发布时官方版本核实）。触控目标至少 44×44 CSS px；支持 VoiceOver/TalkBack、系统文字放大和高对比度；状态不只依赖颜色；界面及验证面向中文输入。
- 所有用户可见文案都经过 i18n；中文是首发语言。日期、时间、数字与单位格式本地化，内部标识和备份 schema 不随语言变化。

## Testing Decisions

### 测试质量

- 测外部可见行为和稳定的领域契约，不断言 React 组件内部状态、hook 调用顺序、IndexedDB 表名或 CSS 类名。
- 使用确定性时钟/本地日期和固定输入；覆盖跨午夜、夏令时/时区边界、部分日记、未知/区间/明确零、异常时间以及边界阈值。
- 数据保存、导入和升级通过可观察的结果验证；失败不得丢失旧数据或出现半写入。
- 脱网、权限拒绝、浏览器不支持、配额失败都应验证安全降级，而不是只测正常路径。

### 测试 seam 与模块

1. **纯领域引擎（最高 seam）**：输入睡眠日记、疗程状态与筛查状态，输出 TIB/TST/SE、完整夜、六周进度、候选窗口、周滴定决定、风险暂停和提醒计划。测试指标公式、夜间时间解析、`<4` 与 `≥4` 完整夜、`SE=85/90%` 边界、5 小时下限、10/12 小时边界、窗口舍入、推迟调整和高风险暂停。
2. **数据仓库边界**：以接口隔离 IndexedDB 实现并提供内存 fake。测试事务、保存/读取、应用/schema 升级、JSON/ZIP 校验、覆盖/新增/取消、ID 去重冲突、失败回滚、损坏与超限文件拒绝。
3. **平台能力边界**：适配文件读写、应用内提醒、可选系统通知、离线与存储持久性。用 fake 测拒绝权限、不支持 API、`persist()` false、QuotaExceededError、文件分享/下载不可用与取消。
4. **应用级集成**：验证六周导航、W1 预览/W2 校准/W3 启动、日记缺失数据状态、风险用户仍可日记/导出、备份提醒开关、错误信息脱敏、i18n 资源完整和离线路由。
5. **真实设备验收**：iOS Safari 标签页与主屏幕 PWA、Android Chrome 安装与离线；写入失败、应用更新、系统清理和手工清站点数据后 ZIP 跨设备恢复；通知拒绝/撤销；VoiceOver、TalkBack、大字、中文输入；CSV 在 Excel/WPS/通用解析器中打开。

当前代码库没有实现或测试先例。建议采用纯领域单元测试、仓库契约测试和少量端到端真机验收；工具选型在技术栈研究报告中列为 PoC，不在本规格指定未验证的测试框架。

## Out of Scope

- 睡眠分期、鼾声/梦话录音、被动手机/手表监测、Apple Health/Health Connect 与可穿戴接入。
- ISI 题目复制、收费授权处理、临床诊断、疾病治疗宣称、处方或医疗人员后台。ISI 仅在许可闸门通过后另行设计。
- 云端账号、数据同步、服务器存储、分析/广告/遥测、邮件恢复。
